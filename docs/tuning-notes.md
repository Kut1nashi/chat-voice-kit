# 调参记录（GPT-SoVITS v4 实测）

全部是在同一台机器、同一段参考音频、同一套整合包上跑出来的对照结果。
有结论、有反例，也有被推翻的假设——照抄结论之前先看它是在什么条件下得的。

## 1. 切分方式：`cut5` 是吐字不完整的元凶

同一句「もしもし、聞こえる？ちゃんと聞こえてる？」，只换 `text_split_method`：

| 切分 | 识别回读 | 净语音时长 |
| --- | --- | --- |
| `cut5` | `ましまし聞こえるちゃんと聞こえてる。`（开头"もしもし"被念歪/吃掉） | 2.93 s |
| `cut0` | `もしもし聞こえる ちゃんと聞こえてる。`（完整） | 3.96 s |
| `cut2` | 与 `cut0` 完全一致（字节相同） | 3.96 s |

`cut5` 按标点把句子切成碎片分别合成再拼接，碎片越短越容易被削。聊天回复又普遍只有一两句，
所以默认取 `cut2`：短句整段合成，长文本照样会分段。

## 2. 随机种子：不固定，语速会飘

同一句话、6 个不同 seed，净语音时长分布在 **1.96 ~ 2.20 秒（差约 12%）**。
`123` 是最慢的一档（约 183 ms/音拍，仍在日语自然区间内），取它最不容易显得"赶"。
设 `seed = -1` 恢复每次随机。

## 3. 输出侧淡出：治错了地方（默认关闭）

需求是"最后一个音又轻又仓促"，第一反应是加输出淡出（120ms、250ms 都试了）——**听感更差**。

真实原因：**参考音频本身结尾是硬切**。实测某参考音频 尾静音 0.000s、末 10ms 窗仍有 21% 振幅、
末 50ms 相邻样本跳变 11.3%；用这段参考生成的输出末段跳变 12.4%——几乎一致。
GPT-SoVITS 是照着参考的韵律收尾的，参考急，输出就急。

于是改成：**参考侧解决**（换结尾自然的参考），输出侧只保留
① 裁掉模型自带的尾静音 ② 首尾补静音（默认 300ms）。
顺手否掉的两个假设：把参考做淡出（跳变 11.3%→2.4%）反而让输出更差（6.5%→11.5%）；
把参考延长到 7.2s 更差（14.3%）。

## 4. 首尾留白：首静音必须自己补

`api_v2` 的输出自带约 **0.20~0.27 秒尾静音**，但**首静音很短**，
很多客户端/播放器会把第一个字削掉。所以默认 `adelay=300` + `apad=0.3`，
补白前先把模型自带的尾静音裁掉（`areverse → silenceremove → areverse`），否则尾巴会叠长。

## 5. 那些"看起来有用其实没用"的参数

| 参数 | 试过的值 | 结果 |
| --- | --- | --- |
| `sample_steps` | 32 / 48 / 64 / 96 | 衰减 135/135/134/132 ms、时长都是 3.11 s —— **无差别**，只是合成从 6.1s 涨到 15.2s |
| `super_sampling` | on / off | 输出**字节完全一致**（298,988 B）—— v3 专用参数，v4 上纯空操作 |
| 句末标点 | `。` vs 无 | **字节完全一致**（184,038 B）—— 句号会被剥掉 |
| 句末标点 | `！` | 166,322 B：更短、尾巴更响、更差 |
| 句末标点 | `…` | 176,162 B：尾巴最顺，最大跳变 1.4% |

## 6. GPT 检查点：训练得少 ≠ 长句不稳

同一句 21 音拍长句 `おはよう。今日もかわいいね。ちゃんと聞こえてるよ。`：

| 检查点 | 时长 | 语速 | 识别回读 | 判定 |
| --- | --- | --- | --- | --- |
| e1（epoch 1/15） | 7.82 s | 344 ms/音拍 | `おはよう 今日も可愛いね ちゃんと聞こえてるよ！` | **完整** |
| e3 | 4.16 s | 170 ms/音拍 | `おはよう 今日も可愛いいね。` | **整句丢失** |

9 音拍短句的语速序列：e1 3.78s、e2 4.24s、e3 4.81s，e4 起骤降到 2.46~2.51s（约 278 ms/音拍）。
e3 在长句上语速反转（534 → 170 ms/音拍），与丢句同时发生。

**被推翻的假设**："训练越少 ⇒ 长输入越不稳"。实际是训练最少的 e1 唯一在长句上完整。

## 7. 识别侧的限制

SenseVoice 的 `language` 若固定为 `'zh'`，**片假名密集的日语会转出乱码**；
平假名为主或中英文正常。用 `VOICE_STT_LANG` 按语种切换。
评估"合成吐字是否完整"时若拿它当裁判，注意这个前提。

## 8. 复现方式

```bash
# 固定文本、只换参数，比字节数和识别结果
node examples/say.cjs "もしもし、聞こえる？ちゃんと聞こえてる？"
node examples/stt-cli.cjs out/<刚生成的文件>.wav
```

判断标准建议同时看三个：**识别回读是否完整**、**净语音时长**、
**末段相邻样本跳变**（`analyze` 类脚本可算，跳变越小收尾越顺）。
只看听感容易在"更清楚"和"更自然"之间来回摇摆。
